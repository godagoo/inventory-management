Factory Inventory Management System

A demo operations dashboard for inventory, orders, spending and demand. A Vue single-page app in the browser reads from a FastAPI service, which serves JSON files it holds in memory. There is no database. Restock orders are the only thing the app writes, and they stay in memory until the server restarts.

System architecture

Three layers, and each one talks only to the layer next to it.

Browser: Vue 3 single-page app

Vite dev server, port 3000 by default
Views and components

Seven routed pages, plus FilterBar, detail modals, tasks and profile menus.

Shared state

useFilters for filters, useI18n for English and Japanese, useAuth for a mock user.

API client

api.js wraps axios and removes any filter set to "all" from the query string.

HTTP and JSON to localhost:8001. The ports differ, so this is cross-origin and relies on CORS.

API: Python FastAPI

server/main.py, port 8001
Routes

Inventory, orders, demand, backlog, dashboard summary, spending, reports and restocking.

Filtering and sums

apply_filters, filter_by_month, and totals per request. restock.py spends a budget on forecast items.

Response models

Pydantic checks the shape of most responses. Summary, spending and report routes have no model.

Python import, once at startup. Editing a JSON file needs a server restart.

Data: JSON files in memory

server/mock_data.py, server/data/

mock_data.py loads each file into a Python object when the server starts. Row counts:

orders 250 transactions 56 inventory 32 demand_forecasts 9 backlog_items 4 spending 3 sections purchase_orders 0

Submitted restock orders live in a list in restock.py, not in a file, and reset on restart.

Data flow

What happens when someone picks Tokyo in the warehouse filter on the Orders page.

  1. The filter changes shared stateFilterBar writes to selectedLocation in useFilters.js. That ref sits outside the function, so every component shares one copy.
  2. The page reactsA watch in Orders.vue fires and reloads the data.
  3. The filters become a querygetCurrentFilters() renames location to warehouse and period to month. api.js drops values of "all" and sends GET /api/orders?warehouse=Tokyo.
  4. The API filters in memoryapply_filters matches warehouse, category and status, then filter_by_month matches the date.
  5. The response is validatedThe result passes through the Pydantic Order model and returns as JSON.
  6. The page re-rendersThe response goes into a ref, computed properties recalculate, and Vue updates the table. Amounts are shown in USD, or in JPY at a fixed rate of 150 for the Japanese locale.

Gaps between the code and its docs

Found while tracing the code. The routes were checked against a running server.

Tasks have no backend api.js and App.vue call /api/tasks, but the route does not exist and returns 404. The errors only reach the console, so adding a task appears to do nothing. The tasks you see are mock data from useAuth.js.
Purchase orders are half built The Dashboard shows a Create PO button, but the PurchaseOrderModal it opens is neither imported nor present in the repo, so it has nothing to show. api.js has purchase order calls that nothing uses, and main.py defines the models but no routes. The button also checks purchase_order_id, which the API never sends. purchase_orders.json is empty.
The Backlog page cannot be reached Backlog.vue exists, but it has no route in main.js and no navigation link. Backlog data only appears on the Dashboard.
Filters do not apply to all data CLAUDE.md says they do, but Reports ignores them, and the backlog count in the dashboard summary is unfiltered.
Reports bypasses the API client Reports.vue calls axios directly with its own hardcoded URL, so the API address lives in two places.
Tests and generator are out of date tests/README.md lists test_orders.py with 15 tests, but that file is not in the repo, so the orders routes have no dedicated tests. The product catalog in generate_data.py uses older categories such as Widgets, which do not match the current data.
Local development only There is no real authentication, CORS allows any origin, and the API binds to 0.0.0.0, so it is reachable from the local network while running.
